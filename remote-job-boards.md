## Scrape-viability verdict

Tested August 2026 — live HTTP probes, web search for existing tools, GitHub repos, and Apify actors.

### TRIVIAL — native API/feed, no auth, no scraping needed

|Board|Method|Details|
|---|---|---|
|**Remote OK**|Public JSON API|`remoteok.com/api` — no auth, no rate limiting. Returns full listing array with id, company, position, tags[ ], description (HTML), salary_min/max, date, apply_url, location. ToS requires link-back. **Caveat:** heavy spam/noise (bus-driver postings, junk listings); needs keyword/tag filtering.|
|**We Work Remotely**|RSS feeds|Per-category RSS: `/categories/remote-programming-jobs.rss`, `/categories/remote-devops-sysadmin-jobs.rss` (25-51 items each). `<data-science>` redirects → 301. Rich XML: title, company, region, category, full HTML description (with salary), pubDate, link. Data Science category available via main RSS.|
|**Free-work**|Server-rendered HTML|Already scraped in this project. `scrape_freework.py` uses httpx + BeautifulSoup. No JS, no auth. 119 jobs captured.|

### DOABLE — structured data, moderate effort (1-2h each)

|Board|Method|Details|
|---|---|---|
|**Hiring Cafe**|REST API (auth-gated)|Community-documented endpoint: `hiring.cafe/api/search-jobs`. Currently returns **401 Unauthorized** — needs auth token extraction from the Next.js frontend JS bundles. GitHub scraper repos exist (`jinijinjaney/hiringcafe-job-scraper`) confirming the API shape: POST with `{size, page, searchState: {locations, searchQuery, dateFetchedPastNDays, workplaceTypes, sortBy}}`, returns `{results: [{v5_processed_job_data: {…}, job_information: {…}}]}` with rich structured data (salary, seniority, workplace type, skills, company info). **Effort:** ~1-2h of frontend reverse-engineering to extract the auth token — highest-value board by volume and filter coverage, so worth the investment.|
|**Just Join IT**|Sitemap → server-rendered pages|`robots.txt` disallows `/api/` (old API dead, confirmed 404). Two parallel avenues: **(A) Sitemap route:** `justjoin.it/sitemaps/active-jobs.xml` → per-offer XML → each offer page is server-rendered HTML (no JS needed). Crawler-sanctioned. **(B) Embedded JSON:** 1.8MB page HTML contains paginated job data as JSON with cursor pagination (`meta.next.cursor`), 1,026 total items for the Data category. Rich fields: body, city, companyLogoThumbUrl, skills, salary (PLN multi-currency with conversion), experience level, employment types, workplace type. Both routes bypass the dead `/api/offers` endpoint.|
### DOABLE — curl_cffi TLS impersonation (no browser, no auth)

|Board|Method|Details|
|---|---|---|
|**Jobgether**|curl_cffi → server-rendered HTML|Previously classified HARD (403 on plain httpx). **Reclassified DOABLE:** `curl_cffi` with Chrome 131 TLS impersonation bypasses the anti-bot block. Returns 796KB server-rendered HTML with 51 job links per category page. Each individual offer page (`/offer/{id}-{slug}`) contains `application/ld+json` JobPosting structured data with title, company, datePosted, employmentType, jobLocationType. Approach: enumerate category pages → extract offer URLs → scrape individual offer pages for JSON-LD. No browser needed. **Effort:** ~1h to write scraper, matching existing free-work pattern.|

### HARD — needs browser or manual cookie bootstrapping

|Board|Method|Details|
|---|---|---|
|**Wellfound**|Playwright → cf_clearance cookie → GraphQL|Cloudflare challenge on both page and `/graphql` endpoint. Even Playwright in headless Chrome gets 403 on GraphQL POSTs. The `subbuwu/wellfound_graphqlscout` repo confirms the working approach: (1) solve Cloudflare challenge in a real browser, (2) extract `cf_clearance` cookie, (3) use cookie + Apollo GraphQL headers for programmatic access. The GraphQL query is well-documented (`operationName: JobSearchResultsX`, filter by customJobTitles, remotePreference, salary ranges). **Technically doable but fragile** — cf_clearance expires, requiring periodic browser re-auth. Could be automated with a Playwright-based cookie refresh. **Effort:** ~3-4h for a robust implementation with cookie rotation.|
|**LinkedIn Jobs**|Auth-gated + legal risk|Needs authenticated session. Apify actors exist but all require login. LinkedIn aggressively blocks scraping — account flagging, rate limiting, legal threats. hiQ v. LinkedIn precedent makes scraping public profiles legally gray. **Recommendation:** skip unless user explicitly accepts the legal/ToS risk. If accepted, the practical path is an Apify actor (cheapest vs. effort of building + maintaining auth).|
